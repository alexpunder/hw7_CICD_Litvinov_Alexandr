# 2. Explain deploy strategy

Дата: 2026-05-08

## Status

Принято

## Context

Текущий процесс "в лоб" вызывает простои, затрагивает всех пользователей при ошибке и делает откат долгим (если новая модель деградирует по метрикам, старую приходится возвращать вручную). Цель - разделить ввод новой версии и переключение пользователей, чтобы получить окно наблюдения, оценить поведение модели на реальном трафике и иметь возможность мгновенного безопасного возврата.

## Decision

Комбинация `Blue-Green` и `Canary`:
1.  `Blue-Green` - создаём безопасную параллельную среду (разделение старой и новой версии), базовая стратегия: два окружения, трафик переключается мгновенно, откат мгновенный.
2.  `Canary` - поверх Blue-Green реализуем постепенное подключение: направляем ~10% трафика на новое окружение для проверки на реальных пользователях перед полным переключением.

## Consequences

*   Команда DevOps должна развернуть и автоматизировать инфраструктуру для Blue-Green и Canary деплоя в CI/CD пайплайне.
*   Следить за совместимостью API и согласованности данных.
*   Необходимость в более сложном мониторинге.
